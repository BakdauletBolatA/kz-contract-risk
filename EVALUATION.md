# Оценка качества

Главный артефакт проекта — не отчёт в PDF, а измеренное качество скрининга
и честное понимание, где оно кончается. Этот файл — журнал измерений:
каждая цифра восстанавливается из JSON в `evals/results/` (там же метрики
по категориям, интервалы, срезы по языку и типу договора, все предсказания
и разбор ошибок `*.errors.md`). Таблица целиком: `kzcr eval table`.

**Коротко:** на синтетике и рукописном срезе правила дают 1.00 — и это
вывод о датасете, а не о системе: он написан тем же автором, что и
правила, и насыщен. На стресс-срезе, написанном против правил, — P 1.00 /
R 0.44. ML-классификатор на новых формулировках не обобщается (F1 0.56 на
test) и используется только как маршрутизатор для LLM. LLM-слой реализован
и покрыт тестами, но на живой модели не прогонялся: при разработке не было
ключа API (как запустить — ниже).

## Методика

### Что считается

Единица — **пункт договора** после сегментации (номер вида `5.2`),
а не находка и не токен: пользователь видит «на этот пункт смотреть».

| Метрика | Что показывает |
|---|---|
| **detection P/R/F1** | пункт помечен / не помечен, категория не важна |
| **strict F1** | совпали пункт и категория: система нашла пункт по верной причине |
| **high R** | доля пунктов с высоким риском, помеченных хоть как-то — пропуск здесь самый дорогой |
| **уровень** | на совпавших парах: точность уровня и доля недооценок |
| **ложные тревоги / чистый договор** | находок на договорах без единой ловушки — здесь теряется доверие |
| **док. F1** | находки о договоре целиком: нет форс-мажора, ответственность только у пользователя |

Интервалы — бутстреп по **договорам** (1000 выборок): пункты одного договора
зависимы, и ресемплинг пунктов дал бы ложно узкие интервалы. Формулы
версионированы (`METRICS_VERSION`), прогон хранит хэш датасета и коммит.

### На чём считается

| Срез | Договоров | Что это |
|---|---|---|
| `dev` | 135 | синтетика; на ней пишутся правила и обучается ML |
| `test` | 135 | синтетика с **другими формулировками** тех же ловушек; не используется при разработке |
| `handwritten` | 6 | написаны вручную другим стилем; один договор без ловушек |
| `stress` | 6 | написаны **после** фиксации правил, специально против них |

Синтетика: аренда (ru и kk), поставка, подряд; 20% договоров без ловушек;
около 20% договоров — с позиции «сильной» стороны (арендодатель,
поставщик, подрядчик), где ловушки против арендатора становятся
**зеркальными**: они в тексте, но не в разметке. Система, которая реагирует
на формулировку, а не на сторону, получает на них ложные тревоги.

Разметка — строго по [docs/LABELING_GUIDE.md](docs/LABELING_GUIDE.md),
написанному до первого правила. Изменения руководства ведутся в его журнале.

### Гарантии честности замера

- Файлы синтетики побайтно совпадают с генератором (тест и CI): разметку
  нельзя «подправить» руками.
- Формулировки ловушек из test не встречаются в dev (тест).
- Эталонный корпус не совпадает ни с одним пунктом eval (аудит нашёл и
  заставил переписать две формулировки).
- Правила фиксировались коммитом **до** первого запуска на test и стресс-срезе.

## Журнал

Итерации правил отличаются коммитом; датасет одинаковый (хэш в скобках).

| Итерация | Коммит | Детектор | dev | test | handwritten | stress |
|---|---|---|---|---|---|---|
| 0 | `33ad98f` | null | R 0.00 | R 0.00 | R 0.00 | R 0.00 |
| 1 | `33ad98f` | rules | F1 1.00 | **P 1.00 / R 0.977**, F1 0.99 [0.98–1.00], high R 0.95 | F1 1.00 | — |
| 2 | `75380ab` | rules | F1 1.00 | F1 1.00 ⚠ | F1 1.00 | — |
| 3 | `89e473a` | rules | F1 1.00 | F1 1.00 ⚠ | F1 1.00 | **P 1.00 / R 0.44**, F1 0.62 [0.47–0.77] |
| 4 | `ee1b26c` | ml | (обучен на dev) | P 0.93 / R 0.40, F1 0.56 [0.49–0.63] | P 1.00 / R 0.48 | P 0.62 / R 0.28 |
| 4 | `ee1b26c` | hybrid (rules+ml) | F1 1.00 | F1 1.00 | F1 1.00 | P 1.00 / R 0.44 |

Датасеты: dev `886a86b3`, test `65fddee9`, handwritten `bbe8ca36`,
stress `b596a654`. Ложных тревог на договорах без ловушек у правил и
гибрида — 0 на всех срезах; у ML — 0,05 на test и 1,0 на стресс-срезе.

⚠ **Test после итерации 1 перестал быть слепым для одной формулировки.**
Единственный тип пропуска на test — «может быть **изменена** Подрядчиком»
(шаблон ловил «изменять/изменить», но не причастие). Исправлено в
итерации 2 отдельным коммитом. Поэтому заголовочная цифра test — из
итерации 1: **P 1.00, R 0.977**. Итерация 3 — уточнение руководства (1.2:
отказ контрагента в ответ на существенное нарушение пользователя — не
ловушка), на синтетике не повлияло.

### Итерация 1–3: правила

- Уровень риска на совпавших пунктах угадан в 100% случаев; недооценок нет.
- Документные находки (нет форс-мажора, односторонняя ответственность):
  F1 1.00 на всех срезах.
- Казахский срез test (15 договоров): F1 1.00.

**Стресс-срез** показывает, где правила кончаются. 10 пропусков из 18:

| Формулировка | Почему правила молчат |
|---|---|
| «1/300 базовой ставки Нацбанка … за каждый день» | ставка не в процентах |
| «73% годовых» | годовая ставка, правило ищет «в день» |
| «оставляет за собой право пересмотра арендной ставки» | нет «вправе / может» |
| «корректировать цены», «100-процентной предоплаты» | синонимы вне словаря |
| «претензии … в момент приемки» | срок не числом |
| «штраф 500 000 тенге» при цене договора 2 000 000 | сумма, а не процент — нужна арифметика по договору |
| «оплата по мере реализации конечным потребителям» | pay-when-paid без слова «оплата от» |
| «өз қалауы бойынша қайта қарауға», «автоматты түрде тағы бір жылға ұзартылады» | казахские формулировки вне словаря |

Ни одной ложной тревоги — в том числе на «жёстком чистом» договоре
(индексация с потолком, удержание долга из депозита, отказ при неуплате).
Правила под стресс-срез **не подгонялись**: он остаётся мерой того, что
должны закрывать LLM и будущие итерации.

### Итерация 4: ML

Логистическая регрессия над «относительным» текстом пункта (роли
заменены на `USER_nom` / `CP_dat`, числа — на токены вроде `RATE_HIGH`).

| Оценка | F1 |
|---|---|
| out-of-fold на dev, группы — договоры | 0.93 |
| out-of-fold на dev, группы — формулировки | 0.40 |
| **test** | **0.56** |

Первая версия выбирала порог по первой оценке и выглядела отлично —
пока не пришла цифра test. Причина: синтетические договоры собраны из
одних и тех же вариантов пунктов, и группировка по договору не мешает
модели их запомнить. Теперь модель хранит обе оценки как вилку, а реальное
качество на новых формулировках лежит между ними.

Поверх правил ML на стресс-срезе добавил бы 1 верную находку и 3 ложные,
на test — 0 и 6. Поэтому в гибриде ML **не выдаёт находки** (порог выдачи
с dev — 0.99: увереннее любого пункта, где правила молчат), а
**маршрутизирует в LLM**: отправляет ~60% «молчащих» пунктов и не теряет
ни одного пропуска правил на стресс-срезе — экономия ~40% вызовов LLM.

### LLM: не прогонялся

Реализовано: Claude (`claude-opus-5`, effort `medium`) через LangChain или
Anthropic SDK, ответ по JSON-схеме, находка только с дословной цитатой из
пункта, кэш ответов, маскирование ИИН/БИН, IBAN, телефонов и e-mail,
серверный фолбэк при отказе модели. Формат запроса и разбор ответа
проверены тестами с подменённым HTTP-транспортом — на живой модели
**цифр нет**.

Запуск (ответы кэшируются в `.cache/llm_responses.sqlite`, повтор бесплатен):

```bash
ANTHROPIC_API_KEY=... kzcr eval run --detector hybrid --split stress
```

Оценка стоимости: стресс-срез — ~35 вызовов, меньше $1; test — ~1300
вызовов (там правила молчат на большинстве пунктов), порядка $15–25.
На test LLM важен как проверка **ложных тревог**: правила там уже
находят всё.

Ожидание, которое прогон должен подтвердить или опровергнуть: рост
recall на стресс-срезе за счёт синонимов и «1/300», «73% годовых»; риск —
ложные тревоги на нейтральных пунктах. Проверка цитаты отсекает
выдуманные основания, но не ошибку суждения.

## Ограничения оценки

1. **Один автор.** Руководство, шаблоны, правила и оба рукописных среза
   написаны одним человеком. Даже test оценивает систему оптимистично;
   стресс-срез — поиск слабых мест, а не заголовочная метрика.
2. **Нет реальных договоров.** Следующий шаг — публичные тексты:
   договоры из решений судов (официальные документы, но их нужно
   обезличить) и типовые формы, утверждённые нормативными актами. Разметка —
   двумя людьми с подсчётом согласия (Cohen's κ) до прогона системы.
3. **Казахский срез** — только аренда, формулировки не вычитаны носителем
   языка с юридической практикой.
4. **Малые срезы** handwritten и stress (6 договоров): интервалы широкие,
   одна ошибка сдвигает recall на 5–6 пунктов.
