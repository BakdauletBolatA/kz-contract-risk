# Разметка для извлечения полей

Эталон лежит в `data/extraction_gold/{dev,test,hard}.jsonl`: 70 договоров
(30 dev, 30 test, 10 hard = рукописный и стресс-срезы из `data/eval`). Тексты
договоров — те же, что в риск-скрининге; разметка полей новая.

## Как размечено — честно

- Документы **синтетические** (шаблонный генератор плюс 10 написанных вручную).
  Числа на них оптимистичнее, чем будут на настоящих договорах.
- Разметка сделана Claude (Anthropic): номер, дата, город, стороны и БИН взяты
  регулярным черновиком (`scripts/draft_gold.py`), условия (срок, пеня,
  подсудность, уведомление, оплата) проверены по тексту каждого договора, правки
  записаны в `scripts/build_gold.py`. **Ни один документ не размечен человеком
  с нуля.** Тест `test_gold_validates_against_schema_and_text` проверяет, что
  номер, БИН, сумма и ставка пени действительно встречаются в тексте.
- Claude же — одна из сравниваемых моделей. Это конфликт интересов: эталон,
  размеченный моделью из того же семейства, может завышать её результат.
  Поэтому в README стоит строка про спот-проверку (см. ниже), а у локальных
  моделей этого смещения нет.
- Срез `test` написан другими формулировками, чем `dev` (так устроен генератор),
  и использовался только для итоговых цифр; промпт правился по `dev`.

## Проверка эталона

Страница `docs/gold_review.html` (создаётся `python scripts/make_review_sheet.py`, в git не хранится) показывает
22 договора: все 15, где DeepSeek или Grok с эталоном не согласились, и 7 случайных из test.

Второй проход 2026-10-05 сделал **ассистент, а не человек**: он сверил спорные поля 15 договоров
с текстом. Из 20 разобранных вердиктов 18 подтвердили эталон. Две предложенные правки я проверил
по тексту и **отклонил**, потому что они опирались на формулировки, которых в договорах нет:

- `st_lease_01`, подсудность. Предлагалось `counterparty_location_court` («суд по месту
  нахождения арендодателя»). В п. 5.1 написано «передаются на рассмотрение в Специализированный
  межрайонный экономический суд г. Алматы» — привязки к месту нахождения стороны нет, по правилам
  это `kz_courts`. Фраза про место нахождения арендодателя взята из другого договора.
- `works_ru_dev_038`, уведомление. Предлагалось `0` («без уведомления»). В п. 7.1 написано «без
  объяснения причин», о сроке уведомления договор молчит — по правилам `null`.

Эталон после этого прохода **не менялся**. Не проверено: 7 случайных договоров и поля, по которым
сильные модели с эталоном совпали (они согласны с разметкой, но эталон размечен тем же семейством
моделей, что и одна из сравниваемых). Проверка человеком остаётся открытым пунктом.

## Правила по полям

| Поле | Правило |
|---|---|
| `contract_number` | как в заголовке, без «№» (`45-П`, `2026/118`) |
| `parties` | ровно две; `name` как в тексте с формой и кавычками; `bin` из реквизитов (БИН/ИИН/БСН/ЖСН), иначе `null` |
| `term_months` | только если срок действия назван числом месяцев/лет в самом договоре. Срок датами («до 31.12.2026», «с 01.03 по 31.01»), срок работ («45 дней», «два месяца»), гарантия — **не** срок договора → `null` |
| `auto_renewal` | `true`, если договор продлевается сам при отсутствии возражений. «Может быть продлён по соглашению» — `false` |
| `price_amount` | сумма в тенге, названная в договоре. Цена «в Спецификации», ставка за 1 кв. м → `null`; `price_period` — `monthly` для аренды за месяц, `total` для общей цены |
| `payment_deadline_days` | число дней на оплату после события (поставка, накладная, акт). Число месяца («до 5 числа»), предоплата 100% → `null`. Несколько сроков (аванс и остаток) → срок остатка |
| `payment_penalty_*` | пеня за просрочку **оплаты** плательщиком (арендатор, покупатель, заказчик), % в день; `cap` — предел в % от долга. Пеня другой стороны (за просрочку поставки, работ, передачи) — не учитывается. Ставка не в процентах за день («1/300 ставки НБ РК», «73% годовых») → `null` |
| `dispute_forum` | `kz_courts` — суд по законодательству РК (в том числе конкретный суд города); `counterparty_location_court` — по месту нахождения/регистрации стороны или истца/ответчика; `aifc_court` — МФЦА; `foreign_arbitration` — LCIA, Стокгольм и т.п. |
| `termination_notice_days` | за сколько дней уведомить об одностороннем отказе. «Один месяц» = 30. «Без уведомления» или «в день отказа» = 0. Нет условия — `null`. Если у сторон сроки разные — `null`; если право только у одной стороны — её срок. Отказ за конкретное нарушение (неуплата) не считается |

## Сколько и чего в эталоне

Каждое значение `null` в эталоне — отдельная проверка на галлюцинацию:
модель, которая угадала срок или цену там, где их нет, засчитывается
в `hallucination_rate`.

## Чего эталон не покрывает

- Сканы и PDF: тексты здесь уже извлечены.
- Договоры длиннее нескольких страниц: все 70 помещаются в окно 8k токенов.
- Услуги, лизинг, займ: схема знает только аренду, поставку и подряд.
- Реальные имена и БИН: в рукописном срезе БИН заведомо недействительные нули.
